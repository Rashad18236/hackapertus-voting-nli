## Versioning and working as two (2026-10-08, from 16:29 UTC)

The embedding merge (PR #5) conflicted in 9 files: two branches ran for hours
from an old starting point, both wrote `src/context.py`, and both appended to
the same docs. These rules and tools make that rare and show who built what.

### Git

- **Short branches named `person/topic`, started from a fresh `main`, merged into `main` through a pull request at least once a day; `main` is merged into a working branch as soon as it moves.** Small conflicts early instead of large ones late. Merge commits, never rebase or force-push, so everyone's checkout stays valid.
- **A pull request template (`.github/pull_request_template.md`) fixes the structure the PRs so far used (Summary, Results on dev, What changed, Checks) and adds who built it and which runs and decisions it adds.** Every PR answers the same questions in the same place.
- **Milestone tags on `main`, one per merged stage: `v0.1-walking-skeleton` (`a8fca1d`, PR #1), `v0.2-contract` (`49f50a3`, PR #2), `v0.3-session-2` (`3fa8f58`, PR #3), `v0.4-session-3` (`56d5627`, PR #4), `v0.5-embedding-merge` (`30e2843`, PR #5).** Any milestone can be rebuilt with `git checkout <tag> && make build`. This session could not push them (HTTP 403 from the session's git proxy, which only accepts its own branch); they are created from a team member's own clone.
- **The organisers' template layout of `track_2a/` is unchanged.** `README.md`, `technical_report.md`, `Makefile`, `src/`, `data/` and `docs/` stay where they were; the new folders are inside `src/` and `docs/`, and the PR template is outside `track_2a/`.

### Code

- **One file per task A context variant in `src/contexts/` (`full.py`, `vote_section.py`, `embed_e5_small.py`); `src/context.py` is only the registry (names, prompt per variant, `select`).** Two people adding variants touch different files plus one line each. Each variant file names its prompt version, so `cli.py` no longer needs a table of them.
- **Behaviour is unchanged.** On all 300 dev task A cases the old and new code build identical prompt text and page sets for `full` and `vote-section`, and for `embed-e5-small` on the 28 cases of 3 booklets with the real model.
- **A variant's name never changes meaning; changed behaviour gets a new name.** Every recorded run then names exactly what ran, as prompt versions already do.

### Runs and results

- **Every run has its own folder in `docs/runs/` with `run.json` (person, date, start time, code, variant, settings, numbers) and `NOTES.md`; new folders are named `YYYY-MM-DD_person_variant_cases`.** Who ran what is in the data, not only in the commit author (22 of 29 commits so far are authored "Claude", for sessions Rashad ran).
- **Existing run folders keep their names.** Reports, decisions and recorded commands point to them. Only `baseline-v0`'s three files moved into a folder (`docs/runs/baseline-v0/`, same file names), because a run needs a folder for its `run.json`; its notes say so.
- **`docs/results.md` and `docs/decisions.md` are generated by `scripts/build_docs.py` and never edited by hand; after a conflict in them, the script is rerun.** Two people adding runs or decisions then write different files.
- **The generator checks every `run.json` against the run's own files** (`official_score.json`, `predictions.jsonl`, `raw_answers.jsonl`): Macro-F1, per-label F1, evidence, token and time means, failed calls and unparseable answers. 15 of the 16 table rows have these files, and all 15 pass. The 16th, `baseline-v0` (pre-contract, our scorer), was checked by hand against `baseline-v0_dev_scores.json`. A unit test fails when the generated pages are out of date or a check fails.
- **The results table changed shape, not content.** New columns: start time, person, run (a link to its folder), cases. Footnotes moved word for word into the notes of the runs they describe; notes sections moved word for word into each run's `NOTES.md`. The re-parse of the 60-case sample (`s2-A60-A-v3-fulldoc-reparsed`, 0.767, unchanged from its run) now has its own row, since every run is a row. Runs that were stopped or are part of another run are listed below the table.
- **Start times come from `started_utc.txt` where it exists, otherwise from the notes; a re-parse carries the start of the run it re-reads; an unknown time stays empty, never guessed** (Kaan's offline retrieval check).
- **The two offline retrieval checks got folders under the new naming** (`2026-10-08_kaan_retrieval-check_embed-e5-small`, `2026-10-08_rashad_retrieval-check_embed-e5-small-merge`, the latter with its console output).

### Decisions

- **One file per stage or session in `docs/decisions/`, named `<YYYY-MM-DD-HHMM>_<person>_<topic>.md` (UTC start); the old sections were moved word for word.** Start times come from the section headings or the stage's first commit. Kaan's entry is named after the earliest recorded time of his work (13:13 UTC, the first attempt of his run), since its start was not recorded.
- **Old decision entries and run notes are not rewritten when code moves; this entry records the move.** They describe what was true at the time. Reports that point readers to code (`session_3_report.md`) got a pointer to the new file.
