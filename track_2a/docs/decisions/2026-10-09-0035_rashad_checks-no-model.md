- **Failures are chosen by call number or by a marker in the request (`STUB_FAIL`, `STUB_GARBAGE`, ...).** Call numbers depend on the order of the cases; markers do not, so the order test can include failures.
- **The contract tests run the real CLI in a subprocess (`python -c` runner around `src.cli.main`).** Exit code, output file and file writes are only real in a separate process; the runner only adds an audit hook and turns off the `.env` reader (the image has no `.env` either).
- **"Only /output and /tmp are written" is checked with a Python audit hook that records every write, plus a hash of the data folder before and after.** Tests run as root here, where read-only file modes do not stop writes; the hook sees every Python-level write regardless. The container run (CI) checks the same at the OS level with a read-only root and read-only `/data`.
