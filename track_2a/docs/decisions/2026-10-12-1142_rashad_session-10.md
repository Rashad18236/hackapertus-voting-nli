- **The fake model's log marks a request "in flight" from the moment its headers have arrived to the moment its answer has been written.** That is what a proxy in front of the model can see; connection set-up before the request arrives is local time (measured separately on the real endpoint).
- **Step 2: `predict()` is split into `prepare()` (all local work: booklet, routing, embedding, messages) and `complete()` (the model call and the response); `predict()` = `complete(prepare())` is the sequential path, kept as `--workers 0`.** The requests do not change, so G1 and G2 against the session 9 reference must hold for both paths (they do).
- **Step 2: the cases are prepared in one forked worker process, not in threads.** With two threads, PDF reading (pure Python) and the creation of the ONNX session (which holds Python's lock for up to 2.45 s, measured in the container) kept the thread that sends requests waiting: task B's second request left 7.6 s late, and two threads reading two booklets at once doubled task A's time to the first request (3.4 to 6.3 s). A process has its own lock. One process, not two: each process has its own caches, so two would read most booklets twice.
- **Step 2: preparation order = cases needing no local model first, then grouped by booklet in order of first appearance.** Task B: the first requests go out while the e5 model loads. Task A: each booklet's later cases are ready as soon as it is read, so the queue rarely runs dry; in input order the first 25 cases each needed a new booklet. The order of work never changes a request.
- **Step 2: one kept connection per thread (`requests.Session`); a connection error is sent once more on a new connection.** Measured on the real endpoint: 486 ms set-up per call with a new connection against 1.2 ms with a kept one. A kept connection the server closed shows up as a connection error, so one resend on a fresh connection is needed; before, a connection error was never retried.
- **Step 2: ONNX threads = the container's CPU limit (cgroup), not the machine's cores.** In a 2-CPU container on 4 cores, 2 threads embedded 124 paragraphs in 9.5-10.1 s against 11.3-12.5 s; the vectors are bit-identical for 1, 2 and 4 threads (checked on 124 paragraphs).
